## 11/4 16:40　⓪ 開発の土台づくり ＋ ①〜⑧ の雛形

**頼んだこと**
§15 ⓪（Hooks・テスト・開発記録・コミットのルール）と、「Webhook 受信・定時送信・締切チェック」の雛形。

**Claude Code の設計判断**
- **判定ロジックを「純粋な関数」に分けた**（`src/rules.ts`）。朝の送信・リマインド・正午判定は、現在時刻を引数で受け取り、LINE や DB に触れない。実際の朝8時を待たずに、テストで「8:13 に Cron が遅れて起動した場合」などを確かめられる。
- **「時刻ちょうど」ではなく「期限が来ていて未処理なら実行」**（§3.4）。Cron が数分遅れても取りこぼさない。
- **二重送信の防止**：送る前に「実行済みの日時がまだ空のときだけ書き込む」更新を行い、1行書き換えられたときだけ送る（`src/db.ts` の `claim`）。Cron が重なって2回起動しても、送るのは片方だけになる。
- **正午判定の直前に状態を読み直す**：11:59:59 に届いた返信を見落として、家族に誤って「お返事がまだありません」を送らないため。
- **日時は UNIX ミリ秒で保存し、日付だけ日本時間の文字列で保存**。日本には夏時間がないので、UTC に9時間足すだけで正しく変換できる。

**私が判断したこと**（仕様書に書かれていなかった3点。Claude Code の案を採用）
1. 登録した当日は、朝の送信・リマインド・正午判定をしない（登録完了の文面「あしたの朝から」と合わせるため）
2. 当日中に送信時刻を早め、まだ送っていなければ、当日から新しい時刻で送る
3. 家族が親用の登録リンクを押してしまったときの返事：「すでにご家族として登録されています。このリンクはご両親のスマートフォンで開いてください。」（③で実装）
