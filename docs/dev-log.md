## 11/4 16:40　⓪ 開発の土台づくり ＋ ①〜⑧ の雛形

**頼んだこと**
§15 ⓪（Hooks・テスト・開発記録・コミットのルール）と、「Webhook 受信・定時送信・締切チェック」の雛形。

**Claude Code の設計判断**
- **判定ロジックを「純粋な関数」に分けた**（`src/rules.ts`）。朝の送信・リマインド・正午判定は、現在時刻を引数で受け取り、LINE や DB に触れない。実際の朝8時を待たずに、テストで「8:13 に Cron が遅れて起動した場合」などを確かめられる。
- **「時刻ちょうど」ではなく「期限が来ていて未処理なら実行」**（§3.4）。Cron が数分遅れても取りこぼさない。
- **二重送信の防止**：送る前に「実行済みの日時がまだ空のときだけ書き込む」更新を行い、1行書き換えられたときだけ送る（`src/db.ts` の `claim`）。Cron が重なって2回起動しても、送るのは片方だけになる。
- **正午判定の直前に状態を読み直す**：11:59:59 に届いた返信を見落として、家族に誤って「お返事がまだありません」を送らないため。
- **日時は UNIX ミリ秒で保存し、日付だけ日本時間の文字列で保存**。日本には夏時間がないので、UTC に9時間足すだけで正しく変換できる。

**私が判断したこと**（仕様書に書かれていなかった3点。Claude Code の案を採用）
1. 登録した当日は、朝の送信・リマインド・正午判定をしない（登録完了の文面「あしたの朝から」と合わせるため）
2. 当日中に送信時刻を早め、まだ送っていなければ、当日から新しい時刻で送る
3. 家族が親用の登録リンクを押してしまったときの返事：「すでにご家族として登録されています。このリンクはご両親のスマートフォンで開いてください。」（③で実装）

**確認したこと**
- 自動テスト 55件がすべて通過（日本時間の変換・朝の送信・リマインド・正午判定・返信の種類・不調ボタンの連打防止・文面チェック・招待コード・署名検証）
- 型検査（`tsc --noEmit`）が通過
- Cloudflare 向けの組み立て（`wrangler deploy --dry-run`）が通過
- Hooks：型エラーのあるファイルを作ると、コミットが止まることを確認

**問題と対処**
- npm 11 は、パッケージのインストール時処理を標準では止める。Cloudflare の開発に必要な `esbuild` と `workerd` だけを許可した。

③ 招待コードの照合と登録、⑥ 不調ボタンの家族通知、⑨ デモモード、⑪ 日次メンテナンス、⑫ ようす、⑭ おやすみ・じかん、⑯ ブロック通知

## 11/4 21:00〜23:00　① 環境構築 → ② Webhook → ③ 登録 → ⑥ 不調ボタン → ⑨ デモモード

**頼んだこと**
§15 ①〜⑨。今夜中に母・義母を登録し、11/5 朝から実運用を始められる状態にする。

**Claude Code の設計判断**
- **⑥ 不調ボタンを予定より先に作った**：P0 の雛形では「押すと記録されるだけ」だった。実運用で母が押しても家族に届かない状態は危ないため、③ 登録と同時に仕上げた。
- **不調通知が家族全員に届かなかったときは、通知の記録を戻す**：そのままだと、30分以内にもう一度押されたときに「さきほどお知らせしました」と返してしまい、実際には誰にも届いていないのに親が安心してしまうため。
- **管理者コードは Claude Code がターミナルの中だけで作って登録**：チャットに秘密情報を残さない（§16.3）。O/0/I/1 を除いた16文字で、スマートフォンでも打ち間違えにくくした。
- **デモモードは「登録した当日は送らない」決まりも無視する**：登録したその場で、朝のメッセージから不調ボタンまでを確かめられるように。

**私が判断したこと**
- GitHub リポジトリは最初から公開で作る
- 母・義母の前に、テスト用の「親」を登録して全体の流れを試す（試した後に登録を削除）

**確認したこと（実機）**
- LINE の Webhook の検証：成功
- 管理者登録、しょうたい → 親を招待 → 登録用リンクから親の登録
- デモ：朝 → 声で返信 → お礼が届く
- 不調ボタン → 家族に即時通知 → まちがえて押しました → 訂正通知
- デモ：リマインド・デモ：正午 → 親にリマインド、家族に未返信のお知らせ
- 自動テスト 55件・型検査：通過

**問題と対処**
- **管理者コードを送っても返事が来なかった** → Webhook URL が未設定で、LINE の自動応答も有効のままだった。スクリーンショットで判明し、設定を直した。その後、登録はできていたのに返事が来なかったため、応答メッセージの失敗理由を記録するように直した（以後は再発なし）。
- **Cloudflare のログインが時間切れ** → ブラウザで「Allow」を押す前に2分が過ぎていた。ログを読んで原因を特定し、やり直した。
- **macOS のプライバシー保護でデスクトップに書き込めない** → 企画資料（デモ台本）はリポジトリの外の別フォルダに置いた。

## 11/5　実運用1日目：見つかった問題と対処（⑫ ようす・③ 招待の改善）

**実運用の結果（11/5 朝）**
- 母・義母とも朝8:00のメッセージが届き、2人とも正午より前に返事（1人は文字、1人は声）。お礼も届き、正午の「お返事なし」通知は出なかった（正しい動き）。
- 1人は朝のメッセージが届く前に、自分から文字で返事をくれていた。これも「その日の返事」として記録された。

**見つかった問題と対処**
- **夜中の0時過ぎに登録したため、翌朝が「登録した当日」扱いになり、送られないところだった** → 2人分は手作業で登録日を直した。そのうえで「午前5時より前の登録は前日の登録として扱う」決まりを私が決め、Claude Code が実装した（テスト付き）。
- **通知の呼び名で「さん」が重なった**（登録名が「〇〇さん」のとき「〇〇さんさん」）→ 「さん・様・ちゃん・くん」などで終わる名前には付けないようにした。
- **「返事が来たら家族に知らせてほしい」と感じた** → 仕様は「返事がないときだけ知らせる」（親の負担と通知の多さを避けるため）。Claude Code は仕様を勝手に変えず、選択肢を説明した。私は当初の設計を守ることにし、代わりに家族が自分で確かめられる **⑫「ようす」** を前倒しで作った（今朝の送信・返事の時刻と方法・この7日間の記録）。
- **最初の招待で、母たちがリンクの開き方と招待コードのコピーに戸惑い、10分ほどかかった。コードは結局手入力した** → 招待のカードに［コードをコピー］［リンクをコピー］ボタンを付け、転送用の説明文（①青い文字を押す ②追加 ③送信）を別メッセージで出すようにした。招待文を丸ごと貼り付けて送っても、文中からコードを取り出して登録できるようにした。友だち追加しただけで止まった人には「リンクをもう一度押してください」と案内する。

**確認したこと（実機）**
- ようす：2人分の今朝の状況が表示された
- 招待：［コードをコピー］でコードだけをコピーできた（以前より操作しやすくなった）
- 自動テスト 67件・型検査：通過

**プライバシー**
- テストの見本データに母の呼び名を使っていたため、一般的な名前（はなこさん）に置き換えた。
